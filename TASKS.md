# TASKS.md

## MVP goal
A merchant opens a PayPal sandbox dispute, reviews a drafted response whose every claim was checked against PayPal API data, approves it, and sees the response sent in the sandbox and the dispute's new state confirmed.

Target dates: core build Nov 9-10; README, license, video and submission Nov 11 (deadline Nov 12, 12:00 PT).

### T-004: Claim schema and deterministic verifier
- Priority: P0
- Status: Done
- Depends on: T-003
- Acceptance criteria:
  - [x] A claim has a value and a claimed source (amount, dates, tracking, etc.)
    - `Claim(type, value, source)` in `dispute_defender/claims/models.py`; rules in ADR-008. Supported types: transaction_id, amount, transaction_date, seller_protection (PayPal) and tracking_number, carrier (merchant record). Dates, amounts and tracking are covered; other claim types are FLAGGED as unsupported.
  - [x] The verifier compares each claim to PayPal API data and marks it verified, flagged or blocked
    - Seen live with `scripts/smoke_verifier.py` on sandbox disputes `PP-R-KXL-10197854` and `PP-R-HBV-10197617`: VERIFIED and BLOCKED both came up, and 8/8 stated expectations were met on each. FLAGGED did not come up live; it was exercised by offline tests only.
    - The live claims were fixed test values written by the author, not generated by a model; model output is T-005.
    - tracking_number and carrier are checked against a test merchant record, not PayPal data.
  - [x] Tests cover a matching claim and a mismatching claim (test command recorded in AGENTS.md once verified)
    - `tests/test_verifier.py` covers matches, mismatches (amount, currency, date, transaction ID, tracking, carrier), FLAGGED cases and invalid values. `.venv/bin/python -m pytest` ran on 2026-11-10: 147 passed, offline. The command is in AGENTS.md.

### T-006: Approval page and send
- Priority: P0
- Status: Todo
- Depends on: T-005
- Acceptance criteria:

  - [ ] Blocked claims cannot be sent
  - [ ] Approving sends the response in the sandbox and the page shows the dispute's new state read back from PayPal
  - [ ] The final state shown is read back from PayPal after sending, never assumed; statuses change on their own and UNDER_REVIEW can be short-lived (T-002)
- Note: `PayPalClient` caches its OAuth token until shortly before `expires_in` and does not retry on a 401 from an API call. If a token is revoked early, every call fails until it expires. For a long-running app, consider dropping the cached token on a 401 and retrying the call once (T-003).
